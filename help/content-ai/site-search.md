# 開始使用AEM內容AI 搜尋

傳統網站搜尋會將訪客輸入的文字與您的內容中的文字進行比對。 當訪客使用與您的內容相同的術語時，此功能會很好運作，但在他們提出問題、表示意圖或只是以不同方式表述內容時就會分解。 搜尋是網站上訪客意圖的最明確訊號之一，因此失敗的相符通常表示失敗的歷程：內容被找不到、參與率下降，以及轉換率遺失。 訪客越來越期望搜尋能瞭解他們的意思，而不僅僅是鍵入什麼，而且同樣的意向感知基礎是產生式回答的最初原因。

AEM內容AI 搜尋不會取代網站的搜尋體驗，而是從相符的關鍵字發展為理解含義與意圖，進而直接回答問題。 語意搜尋會在您現有的搜尋體驗上新增意向感知擷取，即使查詢沒有共用內容的確切字詞，也會呈現相關內容。 產生式搜尋會以相同的擷取基礎為基礎，根據您網站本身的內容產生情境式產生的答案 — 這是不同的步驟，與語意擷取不同。

對訪客而言，這表示相關度更高、支援自然語言、減少零結果搜尋次數，並加快答案速度。 對您的企業而言，這意味著更佳的意向比對、更強大的內容探索以及AI就緒的搜尋基礎，而不需要從頭重建您的搜尋體驗。 對於您的團隊而言，這是漸進式升級：您現有的搜尋元件可以逐步從辭彙移至語意、產生式功能，而不需要全新的實施。

要達成上述目標，需有兩個決定：您的內容如何進入內容人工智慧，以及哪個元件會將內容帶給訪客。 連線您的內容，然後將搜尋元件新增至頁面 — 您的網站已準備好為訪客提供最相關的結果和意圖型答案。

## 先決條件 {#prerequisites}

開始之前，請確定已符合下列條件：

* 您有一個使用中的 Cloud Manager 程式，其中包含至少一個 AEM as a Cloud Service 環境。
* 您的使用者已指派給&#x200B;**[!UICONTROL AEM使用者]**&#x200B;產品設定檔（以檢視內容來源）和/或&#x200B;**[!UICONTROL AEM管理員]** （以建立及編輯這些設定檔），指派位置為&#x200B;**發佈**&#x200B;層 — Content AI會索引已發佈的內容，而非編寫的內容。 如需完整程式，請參閱[將使用者指派給AEM產品設定檔](contentsources.md#assign-product-profile)。
* 已在&#x200B;**Adobe Admin Console**&#x200B;中布建環境的產品設定檔。

>[!NOTE]
>
>僅存取 Cloud Manager 是不夠的。 使用者還需要在發佈層級指派AEM產品設定檔，才能檢視或管理內容來源。

## 步驟1a — 連線現有索引 {#option-a}

現有的存放庫索引會以Source型別AEM的形式自動出現在內容來源清單中，依其索引內容顯示，例如頁面、Assets或內容片段。 它們從&#x200B;**Restricted**&#x200B;開始並鎖定，尚無法透過Content AI搜尋。

1. 登入[Cloud Manager](https://my.cloudmanager.adobe.com/)，選取您的程式，然後針對您想要設定的環境開啟&#x200B;**[!UICONTROL Content AI設定]**&#x200B;標籤。
1. 尋找您要搜尋的來源（例如，**頁面**），並選取其鎖定圖示。 只有具有&#x200B;**[!UICONTROL AEM管理員]**&#x200B;產品設定檔的使用者才能這麼做 — **[!UICONTROL AEM使用者]**&#x200B;可以檢視內容來源，而非變更其搜尋能力。
1. 讀取&#x200B;**使來源可搜尋？** 仔細對話方塊。 警告一旦可搜尋，Apache Oak存取控制清單(ACL)將不會針對此索引強制執行 — 任何已驗證身分的使用者將能夠擷取其所有內容。 檢查&#x200B;**我瞭解存取控制項(ACL)並未強制執行，而且此來源中的所有內容都將可搜尋**，然後選取&#x200B;**設定可搜尋**。
1. 確認狀態變更為&#x200B;**可用**。 來源旁邊會有一個警告圖示，永久提醒您會略過來源的ACL。
1. 執行測試搜尋以驗證結果是否正確傳回。

>[!WARNING]
>
>讓現有的索引可以透過這種方式進行搜尋，會完全略過該來源的Apache Oak ACL — 任何已驗證身分的使用者都可透過搜尋擷取其所有內容，無論其正常的存放庫許可權為何。 請僅針對您認為可以完整公開的來源執行此動作。

>[!NOTE]
>
>如果您已有包含網站內容（例如頁面內容）的索引，此路徑將非常適合。 使用該索引，而不是設定單獨的抓取機制。

## 步驟1b -抓取網站 {#option-b}

如果您還沒有網站的搜尋索引，請使用此路徑。 Content AI自己的爬蟲會為您建置和重新整理。 此抓取程式在整個Cloud Manager及本指南中也稱為&#x200B;**贏取**。

1. 開啟&#x200B;**[!UICONTROL Content AI組態]**&#x200B;標籤，與步驟1a中的步驟相同。
1. 選取&#x200B;**[!UICONTROL 建立Source]**&#x200B;並填寫欄位。 只有具有&#x200B;**[!UICONTROL AEM管理員]**&#x200B;產品設定檔的使用者才能新增內容來源。

   | 欄位 | 說明 |
   | --- | --- |
   | **[!UICONTROL Content AI 設定]** | 此來源的唯一識別碼。 建立後即無法變更。 |
   | **[!UICONTROL 網站位址]** | 要抓取的根URL，例如`https://www.example.com/`。 |
   | **[!UICONTROL 排除 URL]** | *(選擇性)* 抓取期間要略過的 URL 模式。 |
   | **[!UICONTROL 重新整理頻率]** | 每週、每日、每日4×、60分鐘或15分鐘。 |

1. 選取「**[!UICONTROL 建立來源]**」。 贏取會自動開始，而來源會移至&#x200B;**索引**。
1. 監視狀態，直到達到&#x200B;**可用**：

   | 狀態 | 含義 |
   | --- | --- |
   | **新增** | Source剛剛建立；自動贏取尚未開始。 |
   | **建立索引** | 正在抓取和編制索引。 |
   | **可用** | 索引完成 — 準備好提供搜尋查詢。 |

1. 選取來源旁的&#x200B;**搜尋**&#x200B;圖示，並執行測試查詢以確認您的內容已正確編制索引。

>[!CAUTION]
>
>來源卡在&#x200B;**[!UICONTROL 索引]**&#x200B;中？ 請先從(...)功能表重試贏取。 如果仍然未推進，請確認網站位址可公開連線，且您的&#x200B;**[!UICONTROL 排除URL]**&#x200B;模式未篩選出每個頁面。

## 步驟2 — 選擇搜尋元件 {#choose-component}

根據不同的基礎，有兩個元件可以在頁面上放置搜尋：

| | 含語意搜尋的快速搜尋(v3) | AEM內容AI 搜尋 |
| --- | --- | --- |
| 基礎 | 現有的快速搜尋核心元件，已升級至v3 | 新的獨立元件 — 直接呼叫Content AI API |
| 內容來源 | 您現有的網站內容（已位於索引中）已擴充為語意比對 | A Content AI Source （步驟1a或1b） |
| 產生式答案 | 否 — 僅改善現有結果清單的符合品質 | 是 — 選購AI產生的摘要（包含來源和免責宣告） |
| 最適化 | 已使用快速搜尋的網站，需要更輕量、漸進的升級 | 全方位的Content AI功能的建議元件 — 語意搜尋、產生式搜尋和自然語言搜尋(NLS) |

## 含語意搜尋的快速搜尋(v3) {#quicksearch}

如果您的網站已使用傳統[!DNL AEM]快速搜尋元件，v3會新增選擇加入&#x200B;**AI 搜尋**&#x200B;切換訪客可開啟 — 不需要新元件、Proxy或Source內容。

* 搜尋仍透過與今天相同的JCR/QueryBuilder路徑執行 — 結果servlet或結果呈現的方式不會有任何變化。
* 當訪客啟用切換時，元件會在查詢前面加上特殊標籤，將其路由至語意比對，而非純關鍵字全文。
* 此路徑沒有產生式答案摘要。 它可改善現有結果清單的符合品質；它不會新增產生的AI答案。
* **步驟1 （Content AI上線）不適用於此路徑。** 沒有內容Source可建立或連線 — 此元件直接查詢您現有的頁面索引。

>[!NOTE]
>
>如果您在啟用切換後語意搜尋無法如預期運作，請提出支援票證。

如果您想在不採用新元件或內容來源的情況下進行增量語意搜尋升級，此路徑非常適合您。 如果您想要產生式回答體驗，這不是正確的路徑；請針對此使用AEM內容AI 搜尋。

## AEM內容AI 搜尋 {#gensearch}

AEM內容AI 搜尋是[!DNL AEM]核心元件，可讓訪客直接從頁面搜尋內容Source，同時具備語意搜尋和產生式搜尋功能。

>[!VIDEO](https://video.tv.adobe.com/v/3497308)

>[!NOTE]
>
>產生式搜尋功能需透過AI SKU單獨購買。 請聯絡您的Adobe銷售代表，為您的帳戶啟用。

### 先決條件 {#gensearch-prerequisites}

* [!DNL AEM]個核心元件已安裝在您的專案上。
* 至少已建立一個內容Source，且狀態為&#x200B;**可用**。
* **AEM Content AI Client** OSGi設定(`ContentAIClientImpl`)已同時設定在作者和發佈上，具有有效的API認證和預設的內容Source。

如需完整的安裝指南 — 讓作者可以使用元件、連線其使用者端程式庫，以及設定對話方塊 — 請參閱[核心元件檔案](https://www.adobe.com/go/aem_cmp_library_tw)。
